# Reset error = readout error: the v3 reset run

Generated by `python -m nac_bench.reset_analysis configs_v3/reset_sensitivity.json` from `results_v3/reset/runs`, v2's committed runs and Phase 1's Step 6b choices (code commit `d68fa39`). **Status: pre-registered.** The config, its seeds and its Holm family were committed before any count of this run existed. Seen beforehand: every v1 and v2 result at reset 0 and v1's own reset variant (v1 score only). The devices are not new, so this tests v2's frozen decoder-graph score under a second noise setting, not on unseen hardware.

Every v1 and v2 headline used reset error 0, because IBM publishes no reset error. IBM resets a qubit by measuring it and flipping it on outcome 1, so a wrong readout leaves it in |1>: *reset = readout* sets each qubit's reset flip probability to its readout flip probability. Every method selects under the model it is graded in; Qiskit's transpile (levels 1 to 3) and mapomatic read an IBM-shaped Target whose reset carries the readout error. mapomatic's cost charges resets at the readout error in both settings, so its costs do not change; its pick between a placement and its mirror (an exact tie in its cost) can, because the level-3 transpile it starts from reads the reset error.

**Verdict rule:** better if the upper end of the 95% interval for P_L(choice) - P_L(reference) is below 0, worse if its lower end is above 0, otherwise tie (Newcombe hybrid score interval for two proportions; the interval of the difference from the all-placement average for that reference). P_L is the logical error rate per shot; changes are relative to the reference, with 95% intervals. The naive placement is v1's and v2's *fixed* baseline, the first valid placement in lexicographic order. FakeAlgiers is v2's held-out device; FakeJakarta and FakeHanoi are development devices.
